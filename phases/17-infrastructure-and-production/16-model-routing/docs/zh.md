# 模型路由作为降本原语

> 中文译文。代码、命令和标识符保持英文。若与原文不一致，以同目录 docs/en.md 为准。

> 一个动态代理评估每一个请求（任务类型、token 长度、嵌入相似度、置信度），把简单查询发给便宜模型，把复杂的升级到前沿模型。也叫模型级联。生产案例研究显示，在美国/英国/欧盟部署中，等质量下成本降低 20–60%；高流量 SaaS 上 30% 的路由效率提升会变成六位数的年度节省。2026 年的背景是 LLM 推理价格每年下降约 10 倍 — 一个 GPT-4 级 token 从 2022 年末的 $20/M 降到 2026 年的约 $0.40/M。下降的大部分来自更好的服务栈（Phase 17 · 04-09），而不是硬件。路由是你把这次降价转成利润、又不让产品回退的方式。失败模式是便宜模型漂移：路由把 40% 推给更弱的模型，推理任务上的质量下降 3–5%，一个季度都没人注意到。用在线质量指标来把守路由，而不是只用离线评测集。

**Type:** 理解
**Languages:** Python（标准库，玩具级联路由器模拟器）
**Prerequisites:** Phase 17 · 01（托管 LLM 平台）、Phase 17 · 19（AI 网关）
**Time:** ~60 分钟

## 学习目标

- 解释模型级联：便宜优先并做置信度检查，低置信度时升级。
- 枚举四种路由信号（任务分类、提示词长度、与已知困难集的嵌入相似度、第一遍的自置信度）。
- 在目标路由比例和质量损失容忍度下计算期望的混合成本。
- 说出能抓住便宜模型爬升的漂移监控指标（在线质量门控）。

## 问题

你的服务在 GPT-5 上每月花费 $80k。你的分析显示 70% 的查询是简单的：“巴黎现在几点？”“改写这个句子。”Haiku 级模型以 3% 的成本就能完美处理它们。30% 需要 GPT-5 的推理 — 编码、数学、多步规划。

如果你把 70% 路由到便宜模型、30% 路由到昂贵模型，账单在同等产品质量下下降约 65%。这就是路由。诀窍是建造这个代理，同时不让质量回退。

## 概念

### 四种路由信号

1. **任务分类**：简单/复杂/代码生成/数学/聊天。可以是基于规则的分类器、一个小 LLM（Haiku 级，$0.25/M），或与已标注桶的嵌入相似度。输出：路由 = 便宜 / 均衡 / 前沿。

2. **提示词长度**：超过 4K token 的提示词常常需要前沿模型才能连贯。少于 500 token 的提示词通常不需要。

3. **与已知困难集的嵌入相似度**：如果查询接近（余弦 > 0.88）一个已知困难桶，直接升级到前沿。

4. **第一遍的自置信度**：先发给便宜模型；如果模型的对数概率（log-prob）显示低置信度，或者它拒绝，或者输出含糊其辞的语言，就在前沿模型上重试。大约 10% 的流量会增加 P95 延迟，但在其余 90% 上节省 50% 以上。

### 三种模式

**预路由**（分类器在前）：增加约 5–10 ms 延迟；总体最快。

**级联**（便宜优先，低置信度时升级）：中位延迟约 1.2 倍（便宜模型运行加上核验），升级时约 2 倍。质量下限最好。

**集成路由**（对一个样本并行跑便宜模型和前沿模型，由奖励模型挑选）：质量最高，成本最高；只用于关键的 A/B。

### 实现

AI 网关（Phase 17 · 19）暴露路由。LiteLLM 有带回退和成本路由的 `router` 配置。Portkey 有护栏 + 路由。Kong AI Gateway 有基于插件的路由。OpenRouter 的模型市场暴露一个推荐 API。

开源：RouteLLM（LMSYS）、Not Diamond（商业）、Prompt Mule。

### 2026 价格曲线

| 模型档位 | 2022 年末 | 2026 | 变化 |
|-------------|-----------|------|--------|
| GPT-4 级质量 | ~$20/M | ~$0.40/M | 便宜 50 倍 |
| 前沿（GPT-5、Claude 4） | — | ~$3-10/M | 新档位 |

改进的大部分是服务效率 — Phase 17 · 04-09 的核心课程变成了提供方侧的成本下降。路由让你在应用层捕获这些收益，而不是等所有用户都迁到便宜档。

### 漂移才是真正的风险

你的路由把 40% 发给便宜模型。六个月里，任务分布变了（用户更老练，问更长的问题）。路由器没有注意到，因为它的分类器是在第一季度数据上训练的。质量悄悄下降。没有人抱怨得足够大声。你在输掉的一次竞品基准里才发现。

用在线质量指标把守路由：

- 每条路由的用户点赞 / 点踩。
- 每条路由上对留出样本（5%）做自动化 LLM 评判。
- 升级率：如果级联向上升级超过 30%，便宜模型就被过度路由了。
- 每条路由的拒绝率。

### 你应该记住的数字

- 2026 年等质量下的路由节省：案例研究为 20–60%。
- 2022–2026 年 LLM 价格下降：合计每年约 10 倍。
- GPT-4 级，2022 相对 2026：约 $20/M → 约 $0.40/M。
- 级联的延迟影响：中位约 1.2 倍，升级约 2 倍（约 10% 的流量）。

## 练习

1. 运行 `code/main.py`。在什么准确率下限上级联胜过预路由？
2. 你的用户群 30% 是企业（复杂查询），70% 是免费层（简单）。设计路由比例。什么在线指标来把守它？
3. 一条路由让质量下降 2%，但节省 40%。这能交付吗？取决于产品 — 两边都论证。
4. 用 OpenAI / Anthropic API 的 logprob 实现一次置信度检查。你从什么阈值开始？
5. 六个月里，升级率从 8% 爬到 22%。诊断三个原因，以及各自的修复。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| 模型路由 | “成本代理” | 按请求动态选择模型 |
| 模型级联 | “便宜优先再升级” | 跑便宜模型，低置信度时落到前沿 |
| 预路由 | “先分类” | 分类器在前；不重跑 |
| 集成路由 | “并行挑选” | 跑多个，奖励模型选最好的 |
| 升级率 | “向上路由的百分比” | 级联请求中发生升级的比例 |
| RouteLLM | “LMSYS 路由器” | 开源路由器库 |
| Not Diamond | “商业路由器” | SaaS 模型路由产品 |
| 漂移 | “便宜爬升” | 分布变化而路由器没有注意到 |
| 在线质量门控 | “实时检查” | 对实时流量做自动化 LLM 评判采样 |
