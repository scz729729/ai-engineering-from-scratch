## 学习目标

- 解释 Toolformer 的自监督训练信号：只有当执行降低了下一个 token 的损失时，才保留工具标注。
- 说出 BFCL V4 的五个评测类别，以及每一类衡量什么。
- 用标准库实现一个工具注册表，带 schema 校验、参数强制转换和执行沙箱。
- 诊断 2026 年的三个开放问题：长程工具链、动态决策和记忆。

## 问题

早期的工具使用问的是：模型能否预测一次正确的函数调用？现代的工具使用问的是：模型能否跨 40 步把工具串起来，带记忆，带部分可观测，能从工具失败中恢复，并且不幻觉出不存在的工具？

Toolformer 建立了基线：模型可以靠自监督学习何时调用工具。BFCL V4 定义了 2026 年的评测目标。二者之间的缺口，就是生产智能体所在的空间。

## 概念

### Toolformer（Schick 等人，NeurIPS 2023）

想法：让模型用候选 API 调用标注自己的预训练语料。对每个候选执行它。只有当把工具结果包含进去能降低下一个 token 的损失时，才保留这条标注。在过滤后的语料上微调。

覆盖的工具：计算器、问答系统、搜索引擎、翻译器、日历。自监督信号纯粹关于工具是否有助于预测文本——没有人类标签。

规模上的结果：工具使用随规模浮现。较小的模型会因工具标注而变差；较大的模型会获益。这就是为什么 2026 年的前沿模型把很强的工具使用烤了进去，而大多数 7B 模型要可靠，仍需要显式的工具使用微调。

### Berkeley Function Calling Leaderboard V4（Patil 等人，ICML 2025）

BFCL 是 2026 年事实上的评测。V4 的构成：

- **智能体式（40%）**——完整的智能体轨迹：记忆、多轮、动态决策。
- **多轮（30%）**——带工具链的交互式对话。
- **实况（10%）**——用户提交的真实提示词（更难的分布）。
- **非实况（10%）**——合成测试用例。
- **幻觉（10%）**——检测何时不该调用任何工具。

V3 引入了基于状态的评测：工具序列之后，检查 API 的实际状态（例如「文件创建了吗？」），而不是匹配工具调用的 AST。V4 增加了网页搜索、记忆和格式敏感性类别。

2026 年的关键发现：单轮工具调用接近解决。失败集中在记忆（跨轮携带上下文）、动态决策（根据先前结果选择工具）、长程链（20 步以上之后漂移），以及幻觉检测（没有合适工具时拒绝调用）。

### 工具 schema

每个提供方都有一份 schema。细节不同，形状相同：

```
name: string
description: string (what it does, when to use it)
input_schema: JSON Schema (properties, required, types, enums)
```

Anthropic 直接使用 `input_schema`。OpenAI 使用 `function.parameters`。两者都接受 JSON Schema。描述是承重的——模型读它们来挑选正确的工具。糟糕的工具描述是选错工具这类失败的第一根因。

### 参数校验

不要信任任何工具调用。要校验：

1. **类型强制转换。** 模型可能在 schema 说 int 的地方返回字符串 "5"。无歧义就转换；有歧义就拒绝。
2. **Enum 校验。** 如果 schema 说 `status in {"open", "closed"}`，而模型发出 `"in_progress"`，就用一条描述性错误拒绝。
3. **必填字段。** 缺少必填字段 → 立刻把错误观察返回给模型，而不是崩溃。
4. **格式校验。** 日期、电子邮件、URL——用具体的解析器校验，不要用正则。

每一次校验失败都应当返回一条结构化观察，让模型能用正确的形状重试。

### 并行工具调用

现代提供方支持在一个助手轮里并行工具调用。循环是：

1. 模型发出 3 次工具调用，带不同的 `tool_use_id`。
2. 运行时执行它们（相互独立时并行）。
3. 每个结果作为 `tool_result` 块返回，用 `tool_use_id` 关联。

工程规则：把关联 ID 当成承重的。对调它们，你就会把错误的工具路由到错误的结果。

### 沙箱

工具执行就是沙箱边界。细节见第 09 课。短版本：每个工具都应当指明读 / 写表面、网络访问、超时和内存上限。泛泛的 `run_shell(cmd)` 是红旗；具体的 `git_status()` 更安全。

## 动手做

`code/main.py` 实现一个生产形状的工具注册表：

- JSON Schema 子集校验器（只用标准库）。
- 工具注册，带描述、输入 schema、超时和执行器。
- 参数强制转换和 enum 校验。
- 带关联 ID 的并行工具分发。
- 作为结构化字符串的错误观察。

运行：

```
python3 code/main.py
```

轨迹展示一个迷你智能体在一轮里调用三个工具，其中一次故意畸形的调用被拒绝，并带上模型可以据此行动的描述性错误。

## 使用

每个提供方都有自己的工具 schema——Anthropic、OpenAI、Gemini、Bedrock。如果需要多提供方，使用翻译层（OpenAI Agents SDK、Vercel AI SDK、LangChain 工具适配器）。BFCL 是参考基准——如果工具使用是产品的核心，发布前用它跑你的智能体。

## 交付

`outputs/skill-tool-registry.md` 为给定的任务领域生成工具目录、schema 和注册表。包含描述质量检查（每个工具的描述是否告诉模型何时使用它？）。

## 练习

1. 增加一个「空操作」工具，让模型可以显式拒绝使用任何其他工具。在类似 BFCL 的幻觉测试上测量。
2. 为「字符串形式的 int」和「字符串形式的 float」实现参数强制转换。强制转换从哪里开始掩盖真正的缺陷？
3. 为每个工具增加超时和熔断器（连续失败 3 次后，拒绝该工具 60 秒）。这对模型如何恢复改变了什么？
4. 阅读 BFCL V4 的说明。选一个类别（例如「多轮」），用你的智能体跑 10 条示例提示词。报告通过率。
5. 把标准库校验器移植到 Pydantic 或 Zod。Pydantic / Zod 抓住了哪些玩具漏掉的东西？

## 关键术语

| 术语 | 人们怎么说 | 它实际的意思 |
|------|----------------|------------------------|
| 工具调用 | 「工具使用」 | 带已校验 schema 的结构化输出工具调用 |
| Toolformer | 「自监督工具标注」 | Schick 2023——保留那些结果能降低下一个 token 损失的工具调用 |
| BFCL | 「Berkeley Function Calling Leaderboard」 | 2026 年基准：40% 智能体式，30% 多轮，10% 实况，10% 非实况，10% 幻觉 |
| 工具 schema | 「给模型看的函数签名」 | 名称、描述、参数的 JSON Schema |
| tool_use_id | 「关联 ID」 | 把一次工具调用系到它的结果上；并行分发所必需 |
| 幻觉检测 | 「知道何时不该调用」 | V4 类别：没有合适工具时拒绝调用 |
| 参数强制转换 | 「字符串到整数的修补」 | 对可预测的 schema 不匹配做窄修复；有歧义就拒绝 |
| 沙箱 | 「工具执行边界」 | 每个工具的读 / 写表面、网络、超时、内存上限 |
