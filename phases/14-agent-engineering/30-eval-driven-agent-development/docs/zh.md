# 评测驱动的智能体开发

> 中文译文。代码、命令和标识符保持英文。若与原文不一致，以同目录 docs/en.md 为准。

> Anthropic 的指引：“从简单提示词开始，用全面的评测来优化它们，只有在需要时才加入多步智能体系统。”评测不是最后一步。它是驱动 Phase 14 里每一个其他选择的外层循环。

**Type:** 理解 + 动手做
**Languages:** Python（标准库）
**Prerequisites:** Phase 14 全部。
**Time:** ~60 分钟

## 学习目标

- 说出三层评测 — 静态基准、自定义离线、在线生产 — 以及各自用来做什么。
- 解释评测器-优化器紧循环。
- 描述 2026 最佳实践：评测与代码放在一起，在 CI 中运行，把守 PR。
- 把 Phase 14 的每一课连接到它生成的评测用例。

## 问题

智能体能通过演示。它们在生产中以演示无法预测的方式失败。基准回答的是“这个模型大体上有能力吗？”，而不是“这个智能体是不是在为我的产品提交正确的补丁？”答案是：三层评测，持续运行，每一条护栏和学到的规则都映射到一个评测用例。

## 概念

### 三层评测

1. **静态基准** — 代码用 SWE-bench Verified（第 19 课），浏览 / 桌面用 WebArena/OSWorld（第 20 课），通用用 GAIA（第 19 课），工具使用用 BFCL V4（第 06 课）。用于跨模型比较和回退把关。污染是真实的：SWE-bench+ 发现 32.67% 的解答泄漏。始终报告 Verified / 经 +-审计的分数。

2. **自定义离线评测** — 你的产品形态：
   - LLM 作评判（Langfuse、Phoenix、Opik — 第 24 课）。
   - 基于执行（跑补丁，检查测试）。
   - 基于轨迹（把动作序列与金标准比较；OSWorld-Human 显示顶级智能体是金标准的 1.4–2.7 倍）。

3. **在线评测** — 生产：
   - 会话回放（Langfuse）。
   - 护栏触发的告警（第 16、21 课）。
   - 逐步的成本 / 延迟跟踪（第 23 课 OTel span）。

### 评测器-优化器（Anthropic）

紧循环：

1. 提议者生成输出。
2. 评测者评判。
3. 细化直到评测者通过。

这是 Self-Refine（第 05 课）的推广。任何你在意的智能体流程都可以包进评测器-优化器以获得可靠性。

### 2026 最佳实践

- 评测与代码放在一起。
- 在每个 PR 的 CI 上运行。
- 用评测分数把守合并（例如“相对 main 的回退不超过 5%”）。
- 每一条护栏映射到一个评测用例。
- 每一条学到的规则（Reflexion、pro-workflow 的 learn-rule）映射到一个失败用例。

### 把 Phase 14 串起来

Phase 14 的每一课都生成评测用例：

| 课 | 它生成的评测用例 |

| 01 智能体循环 | 预算耗尽、无限循环护栏 |

| 03 Reflexion | 学到的反思在重试时生效 |

| 12 工作流模式 | 每种模式产生正确输出 |
| 13 LangGraph | 恢复精确复现状态 |
| 14 AutoGen Actors | 死信队列抓住崩溃的处理器 |
| 16 OpenAI Agents SDK | 护栏在正确的输入上触发 |
| 17 Claude Agent SDK | 子智能体结果返回给编排器 |
| 19-20 基准 | SWE-bench Verified 分数、WebArena 成功率、OSWorld 效率 |
| 21 计算机使用 | 逐步安全抓住被注入的 DOM |
| 23 OTel | span 发出必需属性 |

如果你的评测套件对每一项都有用例，你就覆盖了 Phase 14。

### 评测驱动开发会在哪里失败

- **没有基线。** 没有上一次已知良好状态的评测无法阅读。存下基线。
- **LLM 评判没有依据。** 评判也会幻觉。CRITIC 模式（第 05 课）— 评判以外部工具为依据。
- **对评测过拟合。** 为评测优化会偏离生产有用性。轮换用例。
- **不稳定的评测。** 非确定性用例造成误报。钉住随机种子，快照状态。

## 动手做

`code/main.py` 是一个标准库评测框架：

- 带类别（基准、自定义、在线）的用例注册表。
- 一个被测的脚本化智能体。
- 评测器-优化器循环：提议、评判、细化，直到通过或达到最大轮数。
- CI 门控：汇总通过率 + 相对基线的回退。

运行：

```
python3 code/main.py
```

输出：逐用例的通过/失败、回退标志、CI 门控裁决。

## 使用

- 把评测用例写在与智能体代码相同的仓库里。
- 通过 CI 在每个 PR 上运行它们。
- 回退时让构建失败。
- 跟踪通过率随时间的变化。
- 把每一次生产失败绑到一个新用例上。

## 交付

`outputs/skill-eval-suite.md` 为一个智能体产品构建三层评测套件，带 CI 门控和回退跟踪。

## 练习

1. 拿一次你的生产失败。写一个能复现它的评测用例。你的智能体现在能通过它吗？
2. 为你的领域构建一份三个维度（事实、语气、范围）的 LLM 评判量规。给 50 个会话打分。
3. 把评测套件接进 CI。回退 ≥5% 时让构建失败。
4. 增加一个轨迹效率指标：智能体走了多少步，相对一条金标准轨迹？
5. 把 Phase 14 的每一课映射到你套件里的一个评测用例。有缺失吗？那就是要补上的缺口。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| 静态基准 | “现成评测” | SWE-bench、GAIA、AgentBench、WebArena、OSWorld |
| 自定义离线评测 | “领域评测” | 在你的产品形态上做 LLM 作评判 / 执行 / 轨迹 |
| 在线评测 | “生产评测” | 会话回放、护栏告警、成本/延迟跟踪 |
| 评测器-优化器 | “提议-评判-细化” | 迭代直到评判通过 |
| CI 门控 | “合并阻断器” | 评测回退时让构建失败 |
| 基线 | “上一次已知良好” | 用来检测回退的参考分数 |
| 轨迹效率 | “相对金标准的步数” | 智能体步数除以人类专家最小值 |
